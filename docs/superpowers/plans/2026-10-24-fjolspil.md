# Fjölspil (multiplayer in the minigames) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Fjölspil" button in the minigames shows a QR code; phones, tablets and PCs join with a name and an avatar and play from their own device, over the same Wi-Fi at home (serve.mjs) or through Cloudflare, with the big screen running the rules.

**Architecture:** The big screen (the page that plays the chapter) is the authority: it opens a room on a signaling server (a WebSocket in `serve.mjs` at home, a Durable Object on Cloudflare), hands each guest a WebRTC data channel in a star, and falls back to relaying through the signaling socket when WebRTC does not come up. Guests send intents (`act`), the host answers each seat with a complete `view` of what that device should show. The room, the seats and the wire protocol are pure modules shared by the Node server and the Durable Object, so one test file proves both.

**Tech Stack:** Plain ES modules, no build step, no npm dependencies at the repo root (only `cloud/` has `wrangler` as a devDependency); Node 25 (`node:test`, global `WebSocket` client); three.js r180 from `dist/vendor/`; WebRTC (`RTCPeerConnection`, `RTCDataChannel`); a hand-written RFC 6455 WebSocket server; Cloudflare Workers with Static Assets and a SQLite-backed Durable Object with the WebSocket Hibernation API; `qrcode-generator` 1.4.4 (MIT) vendored.

**Spec:** `docs/superpowers/specs/2026-10-24-fjolspil-design.md` (Icelandic; sections are cited as "spec §N").

### Task 1: The protocol and the room (pure)

**Files:**
- Create: `remake/engine/fjolspil/protocol.js`
- Create: `remake/engine/fjolspil/room.js`
- Test: `remake/tests/fjolspil-room.test.mjs`

**Interfaces:**
- Produces (`protocol.js`):
  - `CODE_ALPHABET = 'ABCDEFGHJKLMNPRSTUVWXYZ'`, `CODE_LENGTH = 4`, `MAX_GUESTS = 3`, `MAX_SEATS = 4`, `NAME_MAX = 12`, `ROOM_TTL_MS = 7200000`, `PING_MS = 5000`, `MISSED_PINGS = 3`, `RTC_FALLBACK_MS = 4000`, `COVER_AFTER_MS = 20000`, `MAX_MESSAGE_BYTES = 65536`.
  - `makeCode(random = Math.random): string` — 4 letters of the alphabet.
  - `normalizeCode(text): string | null` — trimmed and upper-cased; null unless exactly 4 letters of the alphabet.
  - `randomKey(crypto = globalThis.crypto): string` — 32 hex characters from 16 random bytes (`crypto.getRandomValues`).
  - `message(type, body, extra = {}): object` — `{ v: 1, type, ...extra, body }`.
  - `parseMessage(text): object | null` — JSON whose `v === 1` and `type` is a non-empty string; null for anything else, and null without parsing when `text.length > MAX_MESSAGE_BYTES`.
  - Server message shapes (documented in a comment, used by `room.js`): `welcome { code, join }`, `error { reason }`, `joined { id }`, `left { id }`, `relay { to?, from?, body }`. All carried as `message(type, body)` objects, i.e. `{ v: 1, type: 'welcome', body: { code, join } }`.
- Produces (`room.js`):
  - `createRoom({ now = () => Date.now(), ttlMs = ROOM_TTL_MS, code, join = [] })`. A `conn` is any object the caller uses to find a socket again; the room never calls anything on it.
  - `room.connect(conn, { role: 'host' | 'guest', id, key }) → { ok: true, replaced: conn | null, deliveries } | { ok: false, reason: 'bad-role' | 'bad-id' | 'taken' | 'full' | 'no-host', deliveries }`. `deliveries` is `[{ conn, message }]`.
  - `room.disconnect(conn) → { role, id, deliveries } | null`.
  - `room.route(conn, parsed) → deliveries` (only `relay` is routed; anything else, or a bad shape, gives `[]`).
  - `room.touch()`, `room.expiresAt: number`, `room.isExpired(): boolean`, `room.host: conn | null`, `room.hostKey: string | null`, `room.guests(): [{ id, conn }]`, `room.snapshot(): { code, hostKey, lastSeen }`.
  - `restoreRoom(snapshot, { now, ttlMs, join })` — a room with that host key and clock, no connections.
  - `createRooms({ now, ttlMs, join }) → rooms` with `rooms.connect(code, conn, who)` (creates the room on a host connect; a guest to a code with no room gets `'no-room'`), `rooms.disconnect(conn)`, `rooms.route(conn, parsed)`, `rooms.get(code)`, `rooms.sweep() → [conn]` (every connection of every expired room, which the caller closes).

Rules the tests pin (spec §6.1): a host's connect delivers `welcome { code, join }` to it and `joined { id }` for every guest already connected; a second host with another key gets `taken`, with the same key replaces the first (the first gets `error { reason: 'replaced' }`); a guest with the id of a connected guest replaces it the same way and the host gets `joined` again; the 4th guest gets `full`; a guest while the host is away gets `no-host` (it stays in the room; the registry gives `no-room` when no room exists); a guest's disconnect delivers `left { id }` to the host; the host's disconnect delivers `error { reason: 'no-host' }` to every guest and keeps them; a guest's `relay { body }` goes to the host as `relay { from: id, body }`; the host's `relay { to: id, body }` goes to that guest as `relay { body }`; `to` on a guest's relay is ignored; a relay from the host without a known `to` goes nowhere; every connect, disconnect and routed message touches the room.

**Interfaces:**
- Consumes: `createRooms`, `parseMessage`, `message`, `normalizeCode`, `MAX_MESSAGE_BYTES` (Task 1).
- Produces:
  - `attachFjolspil(server, { rooms = createRooms(...), join = () => [], now, sweepMs = 60000 }) → { rooms, close() }` — listens to the `http.Server`'s `upgrade` event. Paths `/fjolspil/ws/<code>?role=host|guest&id=…&key=…` get a WebSocket; any other path answers `HTTP/1.1 404` and destroys the socket; a code that `normalizeCode` refuses answers `400`. `join()` is called per host connect and its result goes into `welcome`.
  - `parseWsUrl(url): { code, role, id, key } | null`.
  - `lanJoinUrls(port, { interfaces = os.networkInterfaces } = {}) → string[]` — `http://<IPv4>:<port>/remake/spil.html` for every non-internal IPv4, in interface order.
  - Socket behaviour (RFC 6455): handshake with `Sec-WebSocket-Accept`; client frames must be masked; text frames (opcode 1) go to `rooms.route`; `ping` (9) is answered with `pong` (10); `close` (8) is answered and the socket is `rooms.disconnect`ed; a binary frame (2) closes with `1003`; a payload over `MAX_MESSAGE_BYTES` closes with `1009`; fragmented messages are reassembled. Deliveries from the room are sent as JSON text frames. A connect refused by the room sends its `error` message and closes with `1000`. Expired rooms' sockets are closed with `1001` every `sweepMs` (timer `unref`'d).
  - `serve.mjs` main block: `const server = http.createServer(handle); attachFjolspil(server, { join: () => lan ? lanJoinUrls(port) : [] }); server.listen(...)`, and with `--lan` it prints `Fjölspil: http://<ip>:<port>/remake/spil.html` per address under the existing lines.
